# 07709.HK 量化信号系统

这是一个针对香港 `07709.HK`（南方东英 SK 海力士每日 2x 做多产品）的信号原型。它会拉取相关市场数据，计算趋势/相对强弱/流动性因子，并输出仓位和风控建议。

重要边界：

- 只生成交易信号和风险提示，不自动下单。
- 默认使用 Yahoo Finance 免费图表接口，行情通常延迟，不适合直接驱动自动交易。
- 07709 是每日 2 倍杠杆产品，存在每日再平衡、波动损耗、跟踪偏差、买卖价差和流动性风险。
- 输出不构成投资建议；如果以后接券商 API，需要单独实现认证、权限、下单前确认、熔断和审计。

## 覆盖的市场因子

默认配置位于 [`config.example.json`](config.example.json)：

| 逻辑名称 | 默认代码 | 用途 |
| --- | --- | --- |
| `etp` | `7709.HK` | 07709 产品自身价格和成交额 |
| `sk_hynix` | `000660.KS` | SK 海力士趋势 |
| `sk_hynix_us` | `SKHY` | SK 海力士美股/ADR隔夜预期 |
| `kospi` | `^KS11` | 韩国大盘风险环境 |
| `sox` | `^SOX` | 美股半导体风险偏好 |
| `nvda` | `NVDA` | AI/HBM 产业链情绪 |
| `mu` | `MU` | 存储芯片同业情绪 |
| `nasdaq100` | `^NDX` | 美股成长股风险偏好 |
| `usdkrw` | `KRW=X` | 韩元强弱，USD/KRW 下行代表韩元相对走强 |

## 快速运行

离线演示，不访问网络：

```bash
python3 -m tools.quant_07709.cli --demo
```

输出 JSON：

```bash
python3 -m tools.quant_07709.cli --demo --format json
```

拉取默认在线数据：

```bash
python3 -m tools.quant_07709.cli --config tools/quant_07709/config.example.json
```

轮询运行，例如每 15 分钟输出一次信号：

```bash
python3 -m tools.quant_07709.cli --watch --poll-seconds 900
```

## 策略评分

默认因子最高 20 分；如果在配置里填入 `product_nav`，会额外启用 1 分 NAV 溢价因子，最高 21 分：

- SK 海力士站上 20 日均线：2 分
- SK 海力士站上 60 日均线：2 分
- SK 海力士 20 日均线高于 60 日均线：2 分
- SK 海力士 20 日相对 KOSPI 跑赢：1 分
- KOSPI 站上 60 日均线：1 分
- SOX 站上 20 日均线：1 分
- NVDA 站上 20 日均线：1 分
- MU 站上 20 日均线：1 分
- NASDAQ 100 站上 20 日均线：1 分
- USD/KRW 5 日下行：1 分
- SK 海力士美股/ADR 隔夜涨幅超过 5%：2 分
- SOX 隔夜涨幅超过 2%：1 分
- NVDA 隔夜涨幅超过 2%：1 分
- MU 隔夜涨幅超过 2%：1 分
- NASDAQ 100 隔夜上涨：1 分
- 07709 近 5 日平均成交额达到阈值：1 分
- 07709 没有明显溢价：1 分；需要在配置里填 `product_nav`，否则不纳入总分

隔夜因子主要用于处理“美股时段先反映、韩国/香港次日才确认”的情形。例如 SKHY 隔夜上涨 10%，会触发 `sk_hynix_us_overnight_strong` 并加 2 分。

仓位映射：

| 分数 | 默认目标仓位 |
| --- | --- |
| 0-3 | 不超过 20% |
| 4-6 | 不超过 35% |
| 7 分以上 | 不超过 50% |

价格硬风控：

| 条件 | 目标仓位上限 |
| --- | --- |
| 07709 < 58 | 不超过 50% |
| 07709 < 52 | 不超过 30% |
| 07709 < 48 | 不超过 10% |

你的示例风险参数：

- 成本价：110
- 当前仓位：70%
- 从 62 回本需要约 77.4% 涨幅
- 从成本价盈利 60% 的目标价：176

## 下一步扩展

建议先用这个工具跑一段时间的信号，再考虑扩展：

1. 接入付费实时行情源，替代 Yahoo 延迟数据。
2. 添加 Telegram/邮件/企业微信提醒。
3. 添加纸面交易日志，记录每次信号后的假设成交和收益。
4. 如券商支持 API，再实现“信号 -> 人工确认 -> 下单”的半自动流程。
5. 只有在半自动流程稳定后，才考虑自动下单，并必须加入单日亏损上限、最大仓位、重复下单保护和 API 异常熔断。
